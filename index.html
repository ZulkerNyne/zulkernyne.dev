About Me 👋

Backend systems. Security by default. Math brain.

I'm a Math & Computer Science student at the University of Calgary who builds backend systems and SaaS products that ship to real users. I care about the engineering underneath — not just whether it runs, but whether it's correct, maintainable, and ready to scale.

all 5 products are live in production — not localhost demos, not course assignments.

Every project on this page is live and serving real users. My approach to auth, security, and data integrity is the same regardless of the project: JWT auth from scratch, rate-limited endpoints, Zod validation at the boundary, and Prisma schema modelling before writing a single query. These aren't features I add later — they're how I start.

Coming from pure mathematics, I think in systems and invariants. I ask why before I ask how. I've migrated a live production database without losing a single row, designed a 64-slot elastic data model for a SaaS sermon planner, built an atomic credit ledger and waitlist chain for a client gym booking system, and led a 5-person software team building ROS2 architecture from scratch — all as a student, all shipped, all live.

proof-first. then code. always.

Security isn't a feature

I implement auth correctly regardless of what the app is. Refresh token rotation, rate-limited endpoints, input validation — these are engineering defaults, not decisions I make per-project. I read the RFC before I write the implementation.

no Auth0. no shortcuts. just understanding.

Systems before syntax

Pure math trained me to model a system completely before touching the keyboard. Prisma schemas, credit ledgers, elastic data models — I architect for correctness first. I've migrated a live production schema mid-flight without data loss.

invariants first. implementation second.

Internals over abstractions

I read docs and source code. I understand Stack Overflow answers before using them. Shipping to real users taught me what no textbook could — edge cases at 2am, schema gaps you only see under load, the difference between working and correct.

why before how. always.
